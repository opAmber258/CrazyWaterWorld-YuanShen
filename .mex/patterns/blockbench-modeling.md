# Blockbench 建模与落地

## Context

小物件（彩蛋方块、面板类模型）用 Blockbench 的 `java_block` 格式建，导出 JSON 直接放进 `assets/barotrauma/models/block/`。贴图可以由 `tools/gen_*.py` 程序化生成，保证可复现。

已落地案例：`cpu_6700x3d`（2 个 element：基板 2..14 / y 0..2，顶盖 3..13 / y 2..3；两张 128×64 贴图；另有 32×32 物品栏俯视图标）。

## Steps

1. Blockbench 新建 `java_block` 工程；先用 `list_textures` / `create_texture` 把贴图建好。
2. **先定贴图尺寸再摆 UV**：Blockbench 按工程贴图尺寸归一化 UV，而 Minecraft 模型 UV 空间固定是 0…16。两张贴图用同一尺寸（本案 128×64），把 `Project.texture_width/height` 和每张贴图的 `uv_width/uv_height` 设成一致，然后按像素坐标拉 UV，导出时会自动换成 0…16。
3. 控制面数：一个方块 2–3 个 element 足够，细节交给贴图丝印；`credit`/`particle` 键不要漏（缺 `particle` 会被审查指出）。
4. 导出后补资源：`blockstates/<id>.json`、`models/item/<id>.json`、`loot_tables/blocks/<id>.json`、`lang` 中英条目；方块属性在 `ModBlocks` 里配（`.noOcclusion()` 用于非满块）。**方块物品还要在 `ModItems` 用 `blockItem("<id>", ModBlocks.<ID>)` 注册 BlockItem，并加进创造页签**——只注册方块的话玩家拿不到物品，也没法实机放置验证（`cpu_6700x3d` 就是这么接的）。
5. 物品栏图标单独做：方块模型在背包里会显得又扁又平，直接画一张 32×32 俯视图，`item/generated` + `layer0`。

## Gotchas

- **UV 不在 0…16 会被裁成一条**：模型里出现 `"uv": [64, 0, 80, 16]` 这种值说明还用着像素坐标；要么让 Blockbench 导出归一化结果，要么手动换算（除以贴图宽高再乘 16）。
- **两张贴图尺寸不一致时 UV 对不上**：Blockbench 按各自贴图的 `uv_width/uv_height` 归一化，混用 64 和 128 会让顶盖变成细条（2026-11-08 实际踩过）。
- **MSYS 路径不认**：MCP 传文件路径用 `D:/zcodeplayground/...`，`/d/...` 会被当成不存在。
- **MCP 会话会过期**：出现 `Session not found` 时重新 `initialize` 拿 `mcp-session-id`，后续请求带上该 header；不要重启 Blockbench。
- **物品图标不要复用方块模型**：方块模型的正面在 UI 里只有十几像素，丝印全糊；单独 32×32 图标是标准做法。
- 贴图脚本生成的文件要提交（`textures/block/...`、`textures/item/...`），只提交脚本不提交产物会导致游戏里是紫黑格。

## Verify

- [ ] F3+T 后方块外观与 Blockbench 预览一致，无缺失贴图（紫黑）
- [ ] 物品栏图标在 16×16 显示下仍能认出轮廓与文字
- [ ] `blockstates`/`models/item`/`loot_tables`/`lang` 四件套齐全
- [ ] 放置/破坏掉落正常（loot table 指向自身）

## Debug

方块变紫黑：先查 `textures` 键路径与文件名大小写；模型变成薄片：查 UV 是否超出 0…16；物品栏图标是方块投影而不是自定义图：查 `models/item/<id>.json` 是否还是 `parent: block/...`。
