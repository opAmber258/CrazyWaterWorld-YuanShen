# 并发工作占用台账

本文件登记**当前正在被某个会话/分支占用的目录与子系统**。多个 Agent 会话可能同时在本仓库工作，未登记的改动容易互相覆盖。

## 登记规则

1. **开工前**：读本文件的「当前占用」表，确认你要动的目录没有冲突。
2. **动手前**：在表里加一行，写清占用者、目录、分支/工作区、开始时间、预计范围。
3. **收工后**：把自己的行删掉；如果是长期工作（跨多天），改成状态「进行中」并更新「最近活动」。
4. **不要删除别人的行** —— 只维护自己登记的条目。发现别人的行已明显过期（超过 3 天无更新），在备注里写「疑似过期」而不是直接删。

## 已知的并发风险点

- **`art/models/`**：美术资产体积大、目录多，多个会话容易同时新建日期夹或在根目录堆放散件。约定：一个资产一个日期夹，同资产不并行改。
- **`.mex/`**：ROUTER、INDEX、context 下的文件是共享结构。改之前必须 `git fetch` 并在**基于 `origin/main` 的 worktree** 里改，不要直接覆盖工作区副本（2026-11-10 曾因工作区落后丢掉 4 个 pattern 条目）。
- **`src/main/resources/assets/barotrauma/`**：运行时资源，美术整合与代码注册会同时动到这里。
- **`docs/`**：约定类文档多人维护，容易语义漂移。改动前先读最新版本。
