## 0. 一句话定位

在 Minecraft 里开一艘潜艇，带 1–4 名船员往返于海底前哨站与航路之间：接任务、下潜、处理进水/断电/缺氧/伤病，抵达目的地，领赏、升级、继续向深海推进。

---

## 1. 目标玩家与设计目标

### 1.1 目标玩家（已确认）

1. **第一目标：潜渊症老玩家。** 能认出并接受原作系统：氧气、进水、伤病、驾驶、任务、死亡惩罚。重视还原度，能接受复杂界面。
2. **第二目标：2–4 人联机小队。** 希望有人驾驶、有人维修、有人医疗。v1 单人优先，但联机不能崩、状态要同步。

### 1.2 非目标

- 纯 Minecraft 生存/建造玩家：不为其做深度建造内容或长教程。
- 沙盒自由建造玩家：v1 不做造船编辑器。
- 竞技/PvP 玩家：v1 不做 PvP、叛徒模式。

### 1.3 设计优先级（冲突时的裁决顺序）

1. 还原度 > 新手友好
2. 出勤体验 > 沙盒自由
3. 单人可玩 > 多人分工
4. 稳定可玩 > 内容数量

---

## 2. 核心循环（已确认）

**任务出勤循环**：

1. **整备**：在前哨站补给、维修、升级、接任务（1–3 个），在分支地图上选择下一个目的地。
2. **下潜**：驾驶潜艇进入一片任务海域（独立副本）。
3. **途中**：处理环境危机（进水、断电、缺氧、伤病）与生物骚扰；完成打捞/侦察/运送目标。
4. **抵达**：到达目的地 → 本轮结束 → 自动存档 → 结算任务报酬 → 进入下一个前哨站/航路点。
5. **成长**：用报酬买消耗品、修船、升级；沿地图向更深处推进。

**节奏目标**：前期单轮 5–15 分钟，中后期单轮 20–40 分钟。

**失败路径**：死亡 → 复活小艇 → 限时归队；小艇失败或玩家主动结束巡回 → 回档到最近存档。

---

## 3. 战役与长期进度（已确认）

- **形态**：持续战役，一个存档长期玩。
- **地图**：5–7 个地点的小型分支图，每层 2 条路线可选。
  - **前哨站类地点**：可交易、接任务、维修、升级、存档。
  - **航路点**：无设施，抵达后可继续选下一个目的地并自动存档。
- **持久资产**：潜艇、改装/升级、资金、任务进度、玩家角色状态。
- **副本制**：每次出勤生成一片独立任务海域；抵达目的地后回到地图层，不从副本中途自由远航。
- **推进规则**：抵达目的地 = 本轮结束、战役前进；任务成败只影响报酬，不阻断推进。

## 5. 系统需求

### 5.1 船与驾驶

**玩家可见行为**

- 玩家在船内自由行走，通过驾驶台操控潜艇前进/后退/转向。
- 潜艇只能沿船头方向推进，可偏航；不能原地横移。
- 接近前哨站/航路点后可靠泊并触发结算。

**规则**

- 驾驶状态与船内活动互斥：操控时锁定移动，离开驾驶台恢复。
- 无人驾驶时潜艇保持当前位置/缓慢漂流，不自动沉没。

**验收点**

- 能从 A 点开到 B 点并靠泊；船内不穿墙、不卡死；无人时不漂走。

### 5.2 水

- 分舱水位独立计算；破口进水；排水泵只抽本舱。
- 门/舱壁保持水密；开门会过水。
- 水位影响玩家移动与氧气（头部浸没）。
- **验收点**：破口 → 水位上升 → 泵排水；关门阻止蔓延；水淹区移动受阻。

### 5.3 氧气

- 舱内氧气由氧气机维持；断电/破口导致氧气下降。
- 玩家有氧气条；水下/缺氧持续扣血，恢复供氧后回升。
- 氧气瓶可补充个人氧气。
- **验收点**：断氧 → 氧气下降 → 伤害；恢复供氧 → 回升；氧气瓶生效。

### 5.4 电力

- 发电机/反应堆 → 电池 → 用电设备。
- 过载跳闸；断电导致灯、泵、氧气机停摆。
- 不做布线：设备直接接入全船电网。
- **验收点**：关发电机 → 灯灭、泵停、氧气下降；重启恢复；过载可复位。

### 5.5 伤病与医疗（现有系统纳入）

- 6 病种：内伤、流血、烧伤、缺氧、失血、眩晕。
- 6 部位：头、胸、左臂、右臂、左腿、右腿。
- 治疗物品：绷带、止血密封胶、吗啡、血浆包、生理盐水。
- HUD：血条上方摘要 + H 键健康面板。
- **验收点**：摔伤/烧伤/流血/缺氧/失血/眩晕可见可治；死亡清空；存档保留；治疗他人可用。

### 5.6 战斗

- 2 种敌对生物：
  - 1 种船外威胁：撞击船体、制造破口。
  - 1 种船内威胁：入侵船内、近战攻击玩家/设备。
- 玩家武器：至少 1 种近战 + 1 种远程；远程消耗弹药。
- 不做 Boss、不做武器升级树；船内炮塔列为 Should。
- **验收点**：生物能伤害船体/玩家；玩家能击杀；同屏生物数量有上限，不刷怪过量。

### 5.7 任务系统

**三种模板**

| 模板 | 目标 | 时限 | 失败条件 |
|---|---|---|---|
| 打捞 | 到沉船点取回目标物并带到目的地 | 无 | 目标物损毁/未取回 |
| 侦察 | 到达指定坐标/完成扫描 | 无 | 未到达/未扫描 |
| 运送 | 把货物/人员从 A 送到 B | 普通运送无时限；仅另立紧急类才有时限 | 货物损毁/未送达 |

**规则**

- 前哨站任务板接取，每轮 1–3 个 **【默认 3】**。
- 抵达目的地 = 本轮推进；任务完成度只决定报酬。
- 部分完成 → 部分报酬；失败 → 该任务零报酬，但战役继续。
- 时限只用于救援/紧急运送类，打捞/侦察不限时。
- **验收点**：三类任务各完成 ≥1 次；失败/部分完成结算正确；限时任务超时判定正确。

### 5.8 地图与巡回

**2026-11-05 本轮确认范围**：非航行时顶部提示，默认 ~（可重绑）打开海图；首生物群系只做寒冷深穴；左键相邻地点、勾选共享任务（允许空任务）后下潜，安全传送全部在线玩家至潜艇。本轮到此为止，独立任务海域生成明确延后，不能用连续世界/区块卸载冒充。玩家接近地图节点不算物理靠泊，自动到站暂禁。


- 5–7 节点小型分支图；每层 2 条路线可选。
- 地点分前哨站（设施）与航路点（无设施）；两者都可选下一站并自动存档。
- 抵达目的地 → 本轮结束 → 自动存档 → 结算 → 地图层选下一站。
- **验收点**：能完整推进 3 站；分支可选；读档回到正确节点。

### 5.9 经济与升级

- 货币：任务报酬 + 出售物品。
- 支出：消耗品（氧气/燃料/弹药/药品）、船体维修、永久升级。
- 永久升级 3 条线，各 2–3 级 **【默认】**：船体耐久、引擎、氧气系统。
- 价格递增；破产时至少能接基础任务，不出现死锁。
- **验收点**：钱能花出去；升级效果可感知；破产可恢复。

### 5.10 死亡、复活小艇与回档

> **已确认的有意取舍**：原版单人战役没有复活小艇（`SinglePlayerCampaign` 全队死亡 → Game Over → 读档）；复活小艇是多人回合机制。本作 v1 按用户确认，把「小艇归队」统一用于单人，以换取不需要 AI 船员。这是明确的设计偏离，不是还原。

**流程**

1. 玩家死亡 → 进入观战/等待。
2. 单人：立即派艇；多人：死亡/观战比例达到阈值 **【默认 50%】** 后派艇。
3. 复活小艇在任务海域远离主潜艇的水域生成；玩家在艇内复活。
4. 玩家限时 **【默认 120 秒】** 把小艇开回主潜艇并对接。
5. 超时或小艇被毁 → 小艇自动返回前哨站 → 本轮判失败 → 回档到最近存档。
6. 玩家主动「结束巡回」→ 本轮判失败 → 回档到最近存档。
7. 多人全灭 → 仍派艇；艇失败才回档。

**验收点**：死亡 → 艇内复活 → 开回 → 归队；超时 → 回档；回档后资金/船/任务/位置正确。

### 5.11 存档

- **自动**：抵达前哨站/航路点。
- **手动**：任意时刻（战斗中是否允许待定）。
- **内容**：地图进度、资金、潜艇状态、升级、玩家角色、任务状态、库存。
- **回档**：读最近一次存档。
- **验收点**：退出重进状态一致；手动存档/读档一致；回档恢复到存档点。

### 5.12 HUD 与引导

- 常驻 HUD：氧气、血量、伤病摘要、深度、电力/进水警告、任务目标。
- 首次进入世界：目标 HUD + 关键提示（驾驶、氧气、进水、接任务）。
- 不做独立教程关卡；老玩家可跳过。
- **验收点**：新玩家能在提示下完成第一轮出勤。

### 5.13 联机兼容

- 单人优先；2–4 人兼容。
- 共享：潜艇、任务、地图进度、资金。
- 每个玩家独立角色与伤病状态。
- **验收点**：2 人同服 1 小时，能共同登船/驾驶/完成任务，状态同步，不崩溃。

## 8. 验收标准

### 8.1 功能验收（全部通过才算 v1 完成）

1. **完整战役**：新档 → 前哨站 A → 接任务 → 选目的地 B → 下潜 → 完成目标 → 抵达 B → 自动存档 → 接任务 → 选 C → 抵达 C。
2. **任务覆盖**：打捞/侦察/运送各完成 ≥1 次；失败与部分完成各 ≥1 次。
3. **死亡流程**：死亡 → 复活小艇 → 开回主潜艇 → 归队；小艇超时 → 回档。
4. **存档流程**：退出重进状态一致；手动存档/读档一致；回档恢复到最近存档。
5. **升级生效**：三条升级线各至少升 1 级，效果可感知。
6. **医疗系统**：6 病种可触发、可治疗；死亡清空；存档保留。

### 8.2 稳定性验收

- 单人连续游玩 2 小时：无 crash、无存档损坏、无持续内存增长导致 OOM。

### 8.3 性能验收

- 本机、常规航行 + 中等进水：平均 ≥120 FPS。
- 集成服务器：20 TPS。
- 记录基线数据（CPU/GPU/内存）备查。

### 8.4 联机验收

- 2 名玩家、同一专用服务器、连续 1 小时：
  - 能共同登船、驾驶、完成任务；
  - 任务/伤病/船状态同步；
  - 不崩溃、不出现可复现的状态不同步。

### 8.5 发布判定

- 8.1–8.3 全部通过 = v1 可发布。
- 8.4 为兼容性底线；不通过则降级为「单人版发布，联机标注实验性」。
- 任一 Must 系统缺失 = 不发布。

## 9. 风险与开放问题

### 9.1 主要风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| 单人小艇偏离原版 | 老玩家觉得突兀 | 作为难度/设置项；文档明示取舍 |
| 无 AI 船员 | 单人船内无人协助 | 设备自动化（泵/氧气机）；任务难度按单人调 |
| VS2 物理船依赖 | 版本不兼容/行为变化 | 锁定版本；隔离接口层 |
| 水面渲染接缝（已知问题） | 观感受损 | v1 前专项修复；不作为验收硬指标 |
| 120 FPS 性能目标 | 水面/粒子是瓶颈 | 性能预算；分档画质 |
| 小艇实现复杂度 | 新载具+对接+AI 返航 | 先做最小可驾驶原型，再接入死亡流程 |
| 副本生成/存档体积 | 加载慢、存档膨胀 | 海域按需生成；只存差异 |

### 9.2 开放问题（不阻塞本文，但实现前要定）
