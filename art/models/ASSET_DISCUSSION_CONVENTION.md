# 模型资产约定：推送与 Discussion #39 更新规范

适用范围：所有 Blockbench 模型资产（方块 / 道具 / 物品 / 生物）。
配套文档：`BAROTRAUMA_PROP_MODELING_GUIDE_V2.md`（制作与打包规范）。
约定对象：[Discussion #39 · 模型资产统计](https://github.com/opAmber258/CrazyWaterWorld-YuanShen/discussions/39)。

## 1. 命名

- 资产名称 = **中文官方译名 + 官方英文名（驼峰命名）**，如：焊接工具 WeldingTool、手动门 CustomDoor。
- 译名查证来源：游戏目录 `Content/Texts/SimplifiedChinese/SimplifiedChineseVanilla.xml` 的 `<entityname.标识>` 条目；**不得凭印象填写**。
- 非原版实体（自创生物等）使用项目定名，并在讨论条目中注明"非原版实体"。
- 文件夹与文件使用 mod 标识（小写下划线）：`art/models/<标识>_<YYYYMMDD>/`，如 `engine_20261108/`。
- 讨论条目必须同时给出：中文名、驼峰英文名、mod 标识、**资产类型**（方块 / 道具 / 物品 / 生物）。

## 2. 交付四件套（推送前自查）

1. `<资产>.bbmodel` —— Blockbench 5.2.2 主工程；
2. `<资产>.geo.json` —— Bedrock Entity 几何导出；
3. `<资产>_tex.png` —— 像素贴图；
4. `preview_front / back / side / oblique.png` —— QA 预览四向（1200×900、透明底；正面平光、侧/背略暗、斜视 fov 38°）；
5. `README.md`（来历与尺寸换算）+ `validation.json` + `structure_audit.json`；
6. `reference/` 子夹 —— 原作裁切参考、调色板、构建/渲染脚本。

缺四件套的资产不推送、不进讨论。

## 3. 推送

- 遵守 `AGENTS.md`：**默认任务分支 → 提交 → PR → 审核合并**；直推 `main` 须维护者对当次明确授权。
- 推送内容为资产夹整体（含 `reference/`）；**`.work/` 与 `_archive/` 不入仓库**。
- 推送完成后，按第 4 节更新 Discussion #39。

## 4. Discussion #39 更新规范

三个分类，章节顺序固定，不得增删章节：

| 分类 | 含义 | 条目规则 |
| --- | --- | --- |
| ✅ 正式资产 | 已入库 `main` 且定案 | 只放定位链接（工程/变体/动画/geo/贴图/预览），**不内嵌预览图** |
| 🔍 待评选资产 | 同一资产多候选并列 | 每候选一条任务列表项（`- [ ]`）+ 定位链接；**可内嵌预览图**（仅此处允许） |
| 📌 待制作 / 待推送 | 需求池 | 三列表格（资产 / 类型 / 状态）；**不写本地路径** |

流转规则：

1. 资产推送 `main` 后：从「待制作/推送」表格移除该行 → 在「待评选」建子分类（或升入「正式」）。
2. 评选：维护者在候选的任务列表勾选通过的一条 → 该资产移入「正式资产」；落选版本移入 `art/models/_archive/` 并从讨论移除。
3. 链接一律直达仓库内实际文件（`blob/main/...`）；未推送资产不得出现本地路径，只标"已制作，待推送 / 待制作"。
4. **只修改自己推送资产对应的条目**；章节标题、分类说明、命名规范等文档性文字不得改写。

## 5. 预览图缓存（易踩坑）

GitHub 用 Camo 代理缓存外链图片：**同一 URL 的图片内容更新后，页面仍长期显示旧图**。

- 内嵌预览的 URL 必须带版本参数：`?v=<数字>`（如 `?v=20261109`）；
- 该资产的图片文件每次更新后，**递增对应条目的 `?v=`**；
- 「正式资产」只有链接不含内嵌图，无此问题。

## 6. 推送一个资产的快速清单

1. 四件套齐备、命名合规（对照第 1、2 节）；
2. 按第 3 节推送；
3. 更新 Discussion #39：待制作/推送表移除该行 → 待评选建候选（或直接升正式）→ 补定位链接与类型；
4. 内嵌预览带 `?v=`；图片更新时递增；
5. 本约定文档与资产一同维护于 `art/models/`，修改约定需在讨论中公告。
